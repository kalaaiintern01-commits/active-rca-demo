How Active-RCA is wired

An ESP32 edge node turns motor vibration into 18 features per 2-second window and publishes them over MQTT. A bridge on the laptop checks every window against healthy baselines. When the machine drifts out of its band, Claude is asked for the root cause and may order an active test: the node runs at another speed or load, the result comes back as new evidence, and Claude commits to a diagnosis. The dashboard watches all of it live.

One active-test episode

  1. Monitor. The node publishes a telemetry window; the bridge validates it against pdm.telemetry.v1.1.
  2. Gate. Three windows in a row more than 3σ outside the healthy band for that operating point open an episode.
  3. Ask. The bridge sends Claude the evidence (features, z-scores, signature ratios), never the injected label.
  4. Test. Claude ranks causes and, if unsure, orders a test such as 1500 rpm; the bridge sends it on cmd and the TEST LED lights.
  5. Re-ask. The windows at the new operating point come back as fresh evidence.
  6. Commit. Claude names the cause with a probability; rca and alert go out, the ALARM LED latches, the dashboard scores it.
